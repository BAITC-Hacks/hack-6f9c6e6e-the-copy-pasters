# EventMatch KZ: веб-приложение для подбора подрядчиков

**Статус:** дизайн согласован для пользовательского просмотра; реализацию можно планировать после утверждения документа.

## Цель

Перевести текущий модульный Streamlit MVP в веб-приложение с FastAPI и отдельными HTML/CSS/JavaScript файлами. Пользователь задаёт параметры мероприятия и получает максимум три подходящих профиля с проверяемым объяснением каждого совпадения.

## Подтверждённые решения

- Backend: FastAPI; frontend: обычные HTML, CSS и JavaScript без отдельного frontend-фреймворка.
- Интерфейс компактный, в виде списка/таблицы (выбранный макет C), объяснение показывается непосредственно в строке результата.
- Визуальный стиль: тёплая светлая нейтральная основа и терракотовый акцент (выбран вариант 2).
- `data.csv` остаётся источником каталога. В проекте нет отдельной базы данных; исходный датасет не менять без необходимости.
- Не использовать внешние AI-сервисы, платные API или генеративное объяснение.
- Приложение только подбирает варианты; бронирование и отправка заявок не входят в MVP.

## Структура

```text
app.py                         # создание FastAPI-приложения и запуск
event_matcher/
  api/                         # HTTP-маршруты и модели запросов/ответов
  services/                    # подбор, оценка и формирование объяснений
  repositories/                # чтение и нормализация CSV-каталога
  config.py                    # схема данных, термины релевантности и пути
static/
  index.html                   # единая страница поиска и результатов
  css/styles.css               # адаптивная тема и состояния интерфейса
  js/app.js                    # форма, вызовы API и отрисовка ответа
data.csv                       # каталог рядом с точкой входа
README.md                      # установка и запуск
ARCHITECTURE.md                # схема компонентов и потока данных
```

`app.py` собирает приложение и подключает маршруты; правила поиска не помещать в него. `api` проверяет и сериализует HTTP-контракт. `services` переиспользует и при необходимости адаптирует текущие правила из `matching.py` и `explanations.py`. `repositories` загружает профильный каталог из пути, вычисленного относительно файла проекта, а не текущей рабочей папки. `static` отвечает только за браузерный интерфейс.

FastAPI отдаёт страницу и API с одного origin, чтобы не вводить CORS и отдельную сборку frontend. Каталог загружается при старте приложения и доступен сервису подбора в нормализованной форме. Для MVP изменения CSV вступают в силу после перезапуска.

## Сценарий пользователя

1. На одной странице пользователь указывает город, дату, формат мероприятия, категорию и бюджет.
2. Язык и желаемая длительность необязательны; если заданы, они становятся обязательными условиями.
3. После нажатия «Подобрать» интерфейс показывает статус поиска и до трёх строк результата.
4. В каждой строке видны имя, категория, цена «от», наличие на выбранную дату, релевантные факты профиля и индивидуальное объяснение.
5. Метки указывают на синтетический профиль, восстановленный город и восстановленную цену. Эти статусы обозначаются текстом, а не только цветом.
6. При недостаточном количестве совпадений интерфейс показывает все найденные варианты и их число.

Для узкого экрана таблица переходит в вертикальные строки с теми же фактами и объяснением; критичная информация не скрывается за раскрывающимися деталями.

## Контракт API

### `GET /api/options`

Возвращает допустимые значения городов, форматов, языков и категорий из загруженного каталога. При переданном `city` категории ограничиваются этим городом. Frontend не дублирует справочники в коде.

### `POST /api/match`

Запрос содержит `city`, `event_date` (`YYYY-MM-DD`), `event_format`, `category`, `budget_kzt`, и необязательные `language` и `hours`.

Ответ имеет один из статусов:

- `matched` — массив до трёх результатов;
- `no_category` — в выбранном городе нет профиля этой категории;
- `filtered_out` — профили категории существуют, но не проходят остальные условия.

Каждый результат сериализует профильные факты, нужные интерфейсу: стабильный ID, имя, категории, город, цену, форматы, языки, максимум часов, даты занятости, булевы флаги `synthetic`, `city_imputed`, `price_imputed` и строку объяснения. Служебные score и внутренние структуры pandas наружу не выдаются. Для `filtered_out` возвращаются число первичных кандидатов и счётчики причин исключения; причины могут пересекаться.

Некорректный запрос получает HTTP 422 и понятное описание поля. Ошибка чтения каталога или обязательной схемы останавливает запуск с ясным сообщением в терминале; API не должен молча отдавать пустой каталог.

## Правила подбора и объяснения

- Сначала выбрать точное совпадение города и категории.
- Затем исключить профили, занятые в выбранную дату. Дата в `busy_dates` — жёсткое исключение.
- Проверить формат, бюджет, язык (если задан) и длительность (если задана). Отсутствующая цена не проходит бюджетный фильтр. Если запрошена длительность, профиль должен содержать `max_hours` не меньше запрошенного значения; неизвестная длительность не считается совпадением. Если длительность не задана, неизвестное значение не исключает профиль.
- Детерминированно оценивать оставшихся кандидатов по релевантности описания и полей профиля к формату/категории, совпадению необязательных условий и цене. Постоянный ID разрешает ничьи. Одинаковый запрос с тем же каталогом возвращает одинаковый порядок.
- Сформировать максимум три результата с индивидуальным объяснением только по фактам профиля и запроса. Не утверждать доступность, язык, длительность или формат без соответствующих подтверждающих полей.
- Сохранить различие между `no_category` и `filtered_out` и объяснять частые причины отсева.

Существующая лексическая релевантность словарная и ограниченная. В MVP её можно уточнять на имеющихся данных и правилах, но нельзя представлять как семантический AI-поиск.

## Обработка ошибок и пустых состояний

- Нет категории в городе: сообщить об отсутствии таких профилей в каталоге.
- Категория есть, совпадений нет: сообщить это и показать счётчики отсева по занятости, формату, бюджету, языку и длительности.
- Ошибка в форме: подсветить поле и оставить введённые пользователем значения.
- CSV отсутствует, не читается или не содержит обязательные колонки: остановить запуск с сообщением, включающим путь/недостающие поля.
- Сетевой сбой запроса: показать понятное сообщение и дать повторить поиск, сохранив форму.

## Визуальные и доступные состояния

Светлый тёплый фон, тёмный текст, нейтральные разделители и один терракотовый цвет для основного действия/акцентов. Без градиентов, стеклянных панелей и декоративной цветной сетки. Текстовые статусы и метки читаемы без опоры на цвет. Нативные подписи формы, видимый фокус клавиатуры и контрастные кнопки обязательны. Интерфейс не использует эмодзи вместо иконок.

## Проверка и критерии готовности

- Приложение устанавливается по `requirements.txt`, запускается из любой текущей папки и находит соседний `data.csv`.
- Форма загружается, справочники поступают из каталога, поиск возвращает до трёх результатов.
- Подрядчик, занятый в выбранную дату, никогда не появляется в выдаче.
- Повтор одинакового запроса даёт тот же порядок; ранжирование не сводится только к цене или длине описания.
- Объяснение каждого результата основано на значениях его профиля; синтетические и восстановленные данные помечены.
- Отдельно работают статусы `no_category` и `filtered_out`, в последнем видны причины исключений.
- Ошибки валидации, недоступный CSV и сетевой сбой дают понятный пользовательский ответ.
- Макет остаётся читаемым на узком экране и с клавиатурной навигацией.

## Вне объёма

База данных, учётные записи, админ-панель, редактирование каталога, онлайн-бронирование, сообщения подрядчикам, платежи, интеграции и внешние AI API.
