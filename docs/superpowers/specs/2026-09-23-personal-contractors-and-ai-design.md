# Личные подрядчики и ИИ-анализ

## Цель

Расширить EventMatch KZ так, чтобы пользователь мог сохранять собственные профили подрядчиков в своём аккаунте, открывать подробную информацию по выбранному подрядчику и по запросу получать ИИ-анализ, основанный на фактах профиля.

## Текущее состояние и ограничения

- Каталог организаторов загружается из `data.csv`; его нельзя изменять при добавлении пользовательских профилей.
- В проекте уже есть FastAPI, статический клиент и Supabase-параметры в корневом `.env`.
- Текущий поток подбора с жёсткими фильтрами и детерминированным ранжированием остаётся основным и не зависит от доступности OpenAI.
- Пользовательские профили по умолчанию приватны и видны только создавшему их пользователю.

## Выбранный подход

Использовать Supabase Auth для регистрации и входа, Postgres для пользовательских профилей и Row Level Security (RLS) для ограничения строк владельцем. Публичный исходный каталог продолжает поступать из CSV и остаётся общим источником данных.

Подробная карточка открывается при выборе подрядчика. Она показывает доступные факты профиля, включая город, категории, форматы, языки, цену, занятость, описание и отметки качества данных. Если пользователь просит ИИ-анализ, интерфейс вызывает серверный endpoint. Сервер передаёт OpenAI только выбранный профиль и необязательные условия текущего поиска. ИИ кратко объясняет соответствие, сильные стороны и пробелы данных; он не может выдумывать цену, доступность, опыт или гарантии.

Результат ИИ создаётся только по явному нажатию, не участвует в жёстких фильтрах и не меняет стабильный порядок выдачи. Сбой или отсутствие OpenAI-ключа не мешает просмотру карточки и поиску.

## Данные и доступ

- Таблица пользовательских профилей содержит UUID записи, `owner_id` из Supabase Auth, обязательные поля каталога, необязательные поля, источник создания и временные метки.
- RLS включён; чтение, создание, изменение и удаление профиля доступны только его владельцу. Сервер проверяет Supabase access token пользователя и не доверяет переданному клиентом `owner_id`.
- Публичные профили из `data.csv` доступны всем, пользовательские записи остаются личными. При поиске данные объединяются без изменения исходного CSV.
- Создание/обновление проверяет обязательные значения и не принимает произвольные ID или владельца.

## ИИ-анализ и расходы

- `OPENAI_API_KEY` хранится только на сервере в корневом `.env` локально; ключ не отправляется в браузер, не возвращается API-ответом и не записывается в логи.
- Запрос к OpenAI выполняется только endpoint-ом анализа, по запросу пользователя, с ограниченным объёмом входных данных и ответа.
- Ответ маркируется как ИИ-анализ, а рядом остаются исходные данные профиля для проверки.
- Неверный/отсутствующий ключ, сетевой отказ, ограничение API или невалидный ответ показываются пользователю как понятное сообщение; каталог и карточка продолжают работать.
- Настройки расхода API выполняются в OpenAI Platform. Значение в `.env` само по себе не задаёт денежный лимит.

## Основные экраны и действия

1. Гость видит общий каталог и результаты подбора; для личных записей система предлагает войти.
2. Пользователь регистрируется или входит через Supabase Auth.
3. Авторизованный пользователь открывает форму «Добавить подрядчика», заполняет профиль, сохраняет его и видит новую личную запись.
4. Нажатие на подрядчика открывает подробную карточку.
5. Нажатие «ИИ-анализ» загружает анализ именно выбранного профиля; повторный запрос не выполняется автоматически при открытии страницы.
6. Владелец может редактировать и удалять собственные записи; другие пользователи не видят и не меняют их.

## Вне объёма первой версии

- Публикация личных профилей для всех пользователей, совместное редактирование, проверка подрядчиков и бронирование.
- Замена исходного каталога организаторов на Supabase.
- ИИ, который самостоятельно принимает решение о доступности, бюджете или допуске кандидата.
- Автоматический анализ каждого подрядчика или каждого поискового запроса.

## Критерии готовности

- Пользователь может войти, создать личный профиль, открыть, изменить и удалить его.
- Пользователь A не может получить или изменить записи пользователя B, в том числе прямым запросом к API.
- Исходный `data.csv` не изменяется; текущие тесты подбора продолжают проходить.
- Подробная карточка показывает фактические поля профиля и происхождение восстановленных/синтетических данных.
- ИИ-анализ по кнопке использует только фактические данные выбранного профиля и явно обозначает неизвестные сведения.
- Ключ OpenAI остаётся серверным, а ошибки интеграции не ломают каталог.
